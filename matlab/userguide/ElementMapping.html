Element Mapping

Tie each FE element ID to a defined joint. One row per element.

Fields

FieldWhat it sets
Assign to selected rowsThe joint Assign writes into every selected row.
Pattern IDOptional. Written to the selected rows only when not blank. Splits one joint definition across several physical patterns.

What you'll see

  • Joint names match ignoring case. An unknown name asks whether to create the joint, skip the row or cancel.
  • Create Missing Joints adds name-only placeholders. Fill them in on Joint Config before running.
  • A duplicate element ID is flagged amber, not blocked.
  • Importing over an existing mapping asks: Merge (update by element ID) or Replace.
  • Import IDs from Forces pulls the element IDs from the Element Forces page.

Import CSV… file format

ColumnRequiredMeaning
element_idYesFE element ID. No spaces or commas.
joint_nameYesA defined joint's name (case ignored).
pattern_idNoOptional pattern key.
  • Columns are read by position, in this order. A header row is optional.
  • Comma-separated; quoted fields may contain commas. Blank lines and lines starting with # are skipped.
  • Each bad line is reported by number and skipped. The rest still import.
  • Export CSV… writes this layout. On an empty mapping it writes a commented template listing your joint names.

+ Bulk Add… paste format

  • IDs only: separate by commas, spaces, tabs or new lines. All go to the joint picked in the dialog.
  • ID and joint name, one pair per line, separated by a tab (as Excel pastes), a comma, or two spaces.
  • Put non-numeric IDs one per line: E-1, E-2 on one line reads as an ID and a joint name.
  • The dialog shows what it detected before you press Add.
